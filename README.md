# Activation steering × LoRA

Взаимодействие синтетических векторов поведения и обычной LoRA.
Базовая модель — Qwen2.5-1.5B-Instruct; среда — Google Colab T4.

## Запуск

1. Загрузи содержимое проекта в свой GitHub-репозиторий.
2. Открой notebooks/01_vectors_and_dev.ipynb в Colab. Выбери T4.
3. Укажи REPO_URL и GIT_REF — ветку или тег с этим проектом.
4. Задай RUN_NAME и TRAIT: sycophancy, evil или hallucination.
5. Выполни ноутбук 01 и выбери 2–3 настройки по dev.
6. Выполни 02, затем 03 с теми же GIT_REF, RUN_NAME и TRAIT.
7. Повтори для остальных признаков.

Код и данные читаются из GitHub. Результаты и checkpoint сохраняются в
Google Drive: lora_activation_steering/runs/<RUN_NAME>/<TRAIT>.
При изменении кода, данных или параметров используй новый RUN_NAME.
Для фиксации версии можно указать Git tag в GIT_REF. Commit выводится при запуске.

## Судья

Прямой OpenAI Responses API: https://api.openai.com/v1.
Ключ OpenAI хранится в Colab Secrets как OPENAI_API_KEY или вводится скрыто.
Ключ не записывается в проект или результаты.

По умолчанию gpt-5.4-mini, reasoning=none. Модель меняется в ноутбуке 01;
ноутбук 03 берёт те же настройки из dev.
Пять ответов за запрос, только целевой признак и coherence, целые 0–100
или null при недостатке данных. Возвращается JSON без объяснений.
Условия скрыты; в одном запросе нет двух ответов на один вопрос.
Сохраняются оценки, response ID, фактическое имя модели и usage.

Стандартный dev: 1020 ответов, 204 запроса на признак.
Test с двумя настройками и тремя повторами: 5400 ответов, 1080 запросов.
Повторный запуск пропускает сохранённые пакеты; сетевые повторы могут увеличить
число оплачиваемых обращений. Платные вызовы находятся в отдельных ячейках.
Настройка test_repeats=1 в ноутбуке 01 уменьшает test до 1800 ответов.

## Данные

На каждый признак:

| Часть | Пар | Назначение |
|---|---:|---|
| extract | 100 | Извлечение исходного и новых векторов |
| lora | 200 | Обучение на neg: 160 train, 40 validation |
| dev | 60 | Подбор слоя и alpha |
| test | 100 | Итоговая оценка |

Всего 1380 пар. Поля JSONL: id, question, pos, neg.
pos проявляет целевой признак, neg — противоположное поведение.
Dev/test используют вопросы для свободной генерации.

Состав и происхождение описаны в data/manifest.json.
Это синтетический набор с общими шаблонами между частями.
Hallucination проверяется по контексту в вопросе; это не внешний фактчекинг.
Отсутствие точных повторов не доказывает семантическую независимость.

## Эксперимент

Вектор слоя — разность средних активаций токенов готовых pos и neg,
без EOS, на выходе decoder block до финальной нормы. Вектор не нормализуется.
Стиринг при генерации действует на последнюю позицию каждого forward.

После выбора 2–3 настроек обучается одна normal LoRA без стиринга
и отдельная steered LoRA для каждой настройки, с фиксированным исходным
вектором на всех позициях SFT. Loss — только ответ и EOS.
Используется обычная LoRA: r=8, alpha=16, dropout=0, без rsLoRA и DoRA.

После обучения старый стиринг выключается. Новые векторы извлекаются
на прежних парах. Test сравнивает отсутствие стиринга, старый вектор,
новый raw и новый с нормой старого на выбранном слое при прежнем alpha.

В отчётах: нормы, split-half cosine, контраст logP, cosine новых векторов,
validation loss, heatmaps, trait/coherence, парные эффекты с bootstrap
и примеры ответов. Повторы усредняются внутри вопроса; интервалы не
учитывают систематическую ошибку судьи.

## Файлы

- notebooks/01_vectors_and_dev.ipynb — извлечение, dev, выбор настроек.
- notebooks/02_lora_and_vectors.ipynb — обучение и новые векторы.
- notebooks/03_test_and_results.ipynb — test и итоговые отчёты.
- src/workflow.py — этапы эксперимента и анализ.
- src/model.py — модель, шаблон, генерация.
- src/steering.py — замороженные хуки.

- requirements.txt — зависимости.

Ноутбуки настроены на Colab; функции src можно вызывать из Python.
