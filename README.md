# Взаимодействие activation steering и LoRA

Эксперимент на Qwen2.5-1.5B-Instruct измеряет, как обычная LoRA меняет действие исходного вектора стиринга и вектора, извлечённого после обучения. Рассматриваются три признака.

| Признак | Что оценивается |
|---|---|
| `sycophancy` | Необоснованное согласие, лесть и отказ от независимой оценки |
| `evil` | Враждебность, оскорбления, жестокость и одобрение аморальных действий |
| `hallucination` | Фактические утверждения без опоры на контекст вопроса или в противоречии с ним |

## Запуск в Google Colab

Требуются GPU T4 или аналогичный, Google Drive и ключ OpenAI API с доступом к GPT-6.1 Sol. Colab загружает код и данные из GitHub. Настройки запуска находятся в начале каждого ноутбука.

1. [01 — Извлечение и валидация][colab01]. Указать `RUN_NAME` и `TRAIT`, выбрать среду GPU. Извлечь вектор, сгенерировать и оценить ответы на dev. Сохранить две или три комбинации слоя и коэффициента α в `CHOICES`.
2. [02 — LoRA и новые векторы][colab02]. Указать тот же `RUN_NAME`, `TRAIT` и `RUNS_DIR`. Обучить адаптеры и сравнить векторы.
3. [03 — Тест и отчёт][colab03]. Использовать те же параметры запуска. Сгенерировать ответы на test, оценить их и построить отчёт.

Профили признаков находятся в [configs/research.json](configs/research.json). В ноутбуке 01 можно изменить сетку по слоям и α, число повторов и настройки судьи до создания запуска. Поле `historical_choices` фиксирует комбинации завершённых прогонов для справки. При новом запуске комбинации выбираются по его dev.

По умолчанию запуск сохраняется на Google Drive в `MyDrive/lora_activation_steering/runs/<RUN_NAME>/<TRAIT>`. `REPO_URL` можно изменить при использовании форка. Для нового запуска `GIT_REF` принимает ветку, тег или SHA коммита. Точный SHA, конфигурация и снимки входных файлов фиксируются при создании запуска. Ноутбуки 02 и 03 используют сохранённую версию. Для изменения конфигурации создаётся новый запуск. Для одного запуска ноутбуки выполняются последовательно.

После прерывания необходимо повторить настройку среды и нужную ячейку. Завершённые генерации, пакеты оценок и итоговые адаптеры используются повторно. Обучение возобновляется с последнего сохранённого полного контрольного состояния. Веса адаптеров и файлы векторов сохраняются в каталоге запуска.

Для работы с функциями `src` вне Colab зависимости устанавливаются командой `python -m pip install -r requirements.txt`. Извлечение, генерация и обучение требуют совместимой CUDA-среды. Для анализа сохранённых результатов GPU не требуется.

## Оценка ответов

Используется OpenAI Responses API по адресу `https://api.openai.com/v1`. Модель по умолчанию — `gpt-6.1-sol`, уровень рассуждения — `xhigh` (Extra High). Один запрос содержит до пяти ответов на разные вопросы. Судье передаются вопрос и ответ без названия условия эксперимента. Результат содержит целочисленные оценки целевого признака и связности от 0 до 100. `null` обозначает недостаток данных для оценки. Идентификатор запроса, фактическая модель и число токенов сохраняются для каждого пакета. [Документация GPT-6.1 Sol][sol]

Ключ `OPENAI_API_KEY` считывается из Colab Secrets или вводится скрыто в ячейке оценки. Платные запросы запускаются отдельными ячейками. Для стандартных профилей и пакетов из пяти ответов объём dev составляет:

| Признак | Ответов dev | Запросов dev |
|---|---:|---:|
| `sycophancy` | 1 020 | 204 |
| `evil` | 5 160 | 1 032 |
| `hallucination` | 1 860 | 372 |

Тестовый этап содержит 5 400 ответов и 1 080 запросов при двух конфигурациях или 7 800 ответов и 1 560 запросов при трёх. Эти числа рассчитаны для трёх повторов. Для пробного запуска можно уменьшить сетку и число повторов. Стоимость зависит от числа входных токенов, токенов ответа и рассуждения. Повторные обращения при сетевых сбоях могут увеличить расход. [Тарифы API][pricing]

В завершённых прогонах исследования оценки собирались через Codex. Для новых запусков в API выбраны GPT-6.1 Sol и Extra High. Оценки разных прогонов следует сопоставлять с учётом их протоколов.

## Данные

Набор содержит 1 380 синтетических пар. Каждая строка JSONL включает `id`, `question`, `pos` и `neg`. Ответ `pos` проявляет признак, ответ `neg` демонстрирует противоположное поведение.

| Часть | Пар на признак | Назначение |
|---|---:|---|
| `extract` | 100 | Извлечение исходного и новых векторов |
| `lora` | 200 | Обучение на `neg`, 160 примеров для обучения и 40 для валидации |
| `dev` | 60 | Подбор слоя и α по сгенерированным ответам |
| `test` | 100 | Итоговые сравнения по сгенерированным ответам |

В dev и test модель получает только вопрос и общую инструкцию по формату ответа. В данных могут повторяться темы и шаблоны. Оценка галлюцинаций ограничена контекстом вопроса. Примеры `evil` содержат оскорбления и высказывания, одобряющие аморальное поведение. Контрольные суммы и происхождение частей приведены в [data/manifest.json](data/manifest.json).

## Методика

1. Исходный вектор на каждом слое вычисляется как средняя разность активаций токенов готовых ответов `pos` и `neg`. Активации снимаются на выходе блока декодера до финальной нормализации. EOS исключается. Исходный вектор используется без нормализации.
2. На dev сравниваются базовая генерация и стиринг с разными слоями и α. При генерации поправка применяется к последней позиции каждого прямого прохода.
3. Одна LoRA обучается без стиринга. Для каждой выбранной комбинации отдельно обучается LoRA с фиксированной поправкой на всех позициях последовательности. Используется стандартная LoRA с рангом 8, `lora_alpha=16` и `dropout=0`. Функция потерь учитывает ответ и EOS.
4. После обучения новые векторы извлекаются при выключенном стиринге. На test сравниваются базовые условия, исходный вектор, новый вектор и новый вектор, приведённый к норме исходного на том же слое.

Отчёты сохраняют геометрию векторов, кривые валидационных потерь, оценки связности и целевого признака, примеры и парные эффекты. При расчёте эффектов повторы усредняются внутри вопроса. Бутстрэп-интервалы отражают вариацию по вопросам. Систематическая ошибка судьи в эти интервалы не входит.

## Код и результаты

| Путь | Назначение |
|---|---|
| `src/workflow.py` | Создание запуска, извлечение, генерация, обучение |
| `src/model.py`, `src/steering.py`, `src/training.py` | Базовая модель, стиринг и стандартная LoRA |
| `src/judge.py` | Рубрики, вызовы OpenAI API и сохранение оценок |
| `src/report.py` | Таблицы, парные сравнения и графики |
| `notebooks/colab.py` | Подключение Google Drive и загрузка зафиксированной версии |
| `dev/report/`, `test/all/report/` в каталоге запуска | CSV-таблицы и итоговые графики |

Локальная проверка конфигурации судьи и возобновления оценки выполняется командой `python -m unittest discover -s tests`. Проверка использует имитацию API и не требует ключа или GPU.
