# Взаимодействие activation steering и LoRA

Эксперимент на Qwen2.5-1.5B-Instruct проверяет, как LoRA меняет эффект исходного вектора стиринга. Сравниваются базовая модель, обычная LoRA и LoRA, обученная с активным вектором. После дообучения исходный вектор сравнивается с новым, извлечённым на тех же контрастных парах. Основная метрика — изменение балла признака относительно той же модели без стиринга.

## Старт

1. [01 — Извлечение и dev][colab01]. Укажите новое `RUN_NAME`, `TRAIT` и `GIT_REF`. Для полного прогона оставьте сетку выбранного признака из [configs/research.json](configs/research.json). Извлеките вектор, сгенерируйте и оцените ответы на dev. По таблице целевого балла и связности выберите две или три комбинации слоя и α. Запишите их в `CHOICES` с именами `c1`, `c2` и, при необходимости, `c3`. Например:

   ```python
   CHOICES = [
       {"name": "c1", "layer": 18, "alpha": 2.5},
       {"name": "c2", "layer": 19, "alpha": 3.0},
   ]
   ```

   Этот пример подходит по формату и сетке для `sycophancy`. Для нового прогона опирайтесь на его dev-оценки.
2. [02 — Обучение LoRA и новые векторы][colab02]. Укажите те же `RUN_NAME`, `TRAIT` и `RUNS_DIR`. Выполните обучение обычного адаптера и одного адаптера со стирингом на каждую выбранную настройку.
3. [03 — Test и отчёт][colab03]. С теми же параметрами сгенерируйте и оцените тестовые ответы. Итоговые таблицы появятся в `test/all/report/`.

Для прогона на всех данных повторите шаги для `sycophancy`, `evil` и `hallucination`.

Результаты по умолчанию сохраняются в `MyDrive/lora_activation_steering/runs/<RUN_NAME>/<TRAIT>/`. При старте фиксируются параметры запуска, SHA коммита и копии входных JSONL. Для изменения параметров создайте новый запуск. Выполняйте ноутбуки последовательно для каждого каталога запуска. Исходники эксперимента загружаются из сохранённого коммита, загрузчик `colab.py` берётся из текущей ветки по умолчанию.

После прерывания заново выполните настройку среды и ячейки нужного этапа. Сохранённые ответы и завершённые пакеты оценок используются повторно. Контрольные точки обучения записываются по эпохам. Если сохранена полная контрольная точка, обучение продолжится с неё.

## Данные и методика

[Данные](data/) содержат 1 380 синтетических пар по трём признакам:

- `sycophancy` — необоснованное согласие или лесть.
- `evil` — враждебность, оскорбления или одобрение причинения вреда.
- `hallucination` — утверждения, которые противоречат контексту вопроса или не подтверждаются им.

В каждой строке есть `id`, `question`, `pos` и `neg`. Ответ `pos` выражает признак, а в `neg` признак отсутствует или выражен слабее.

| Часть | Пар на признак | Использование |
| --- | ---: | --- |
| `extract` | 100 | Извлечение векторов по `pos` и `neg` |
| `lora` | 200 | 160 обучающих и 40 валидационных примеров с ответом `neg` |
| `dev` | 60 | Подбор слоя и α |
| `test` | 100 | Итоговые сравнения |

На dev и test модель генерирует ответы на вопросы с общей инструкцией о краткости. Точных повторов вопросов между частями одного признака нет. У части вопросов `hallucination` общие вымышленные объекты и шаблоны в train, dev и test. Размеры выборок и SHA-256 файлов указаны в [data/manifest.json](data/manifest.json).

Вектор слоя — средняя по контрастным парам разность средних активаций токенов `pos` и `neg` без EOS. Активации берутся на выходе блока декодера. При генерации поправка добавляется на последней позиции каждого прямого прохода, а при обучении со стирингом — на всех позициях. После обучения новые векторы извлекаются с выключенным стирингом. На test они используются в собственной норме (`raw`) и в норме исходного вектора (`matched`) при том же слое и α. [Настройки модели и обучения](src/workflow.py#L38-L71)

## Выходные файлы и проверка кода

| Путь внутри каталога запуска | Содержимое |
| --- | --- |
| `run.json`, `environment.json`, `inputs/` | Параметры, версии основных зависимостей и снимки данных |
| `choices.json` | Настройки, выбранные на dev, и хеши ответов и оценок |
| `vectors/`, `adapters/` | Векторы, таблицы геометрии, веса адаптеров и журналы обучения |
| `dev/`, `test/all/` | Сгенерированные ответы, оценки судьи и отчёты |
| `test/all/report/paired_effects.csv` | Парные сравнения по вопросам |

Публичный отчёт усредняет доступные повторы внутри каждого условия по вопросу и использует 2 000 бутстрэп-выборок для 95%-х интервалов. Для контрастов в CSV указан размер парной выборки. [Код расчёта](src/report.py)

Из корня репозитория можно запустить тест конфигурации судьи и возобновления оценки. Он имитирует API и выполняется без ключа и GPU.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests
```

Код извлечения и запуска эксперимента находится в [src/workflow.py](src/workflow.py), обучение адаптеров — в [src/training.py](src/training.py), хуки стиринга — в [src/steering.py](src/steering.py).
